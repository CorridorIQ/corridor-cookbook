# The eight Decompose My Workflow questions

From a Corridor Context shared-skills session. Ask them in order, two to four per round, each with concrete options and a recommendation. Verbatim below so the wording stays intact.

1. The target. What is this workflow called, how often does it run, and what
   is the finished product? What is the single biggest time sink inside it?
2. The files. Which files does it read from and write to? Ask me for each:
   the source data export, the working model or template, and the most
   recent finished output.
3. The steps. Walk me through it: what do I update first, second, third?
   State each step precisely enough that someone new could follow it.
4. The sources. For every number or input, where does it come from, and how
   would I check that it is right? Flag anything that lives in someone's
   head, an email, or a meeting instead of a file.
5. Judgment vs mechanical. For each step, is it a fixed rule or does it need
   my judgment? Mark the judgment steps; those stay human.
6. What good looks like. What checks prove a run is correct? What totals
   must tie out, and what prior finished output do we compare against?
7. The boundaries. What should never happen? Which files or fields must
   never be touched? What does a human have to sign off on?
8. The traps. Are there two things with confusingly similar names? Do
   different people do the same step two different ways?

## How to run the session

1. Ask one round at a time. Wait for the answers before moving on.
2. When the user mentions a file, ask them to add it to the project so it can be read.
3. When answers conflict, point it out and ask which one is right.
4. Keep a running outline of the workflow as you go, and show the one-paragraph summary firming up.

The output of start is not files. It is one paragraph the user agrees with, handed to scaffold. Scaffold turns the answers into the folder, the plan skill turns them into the plan.
